# Research Report System

ระบบรายงานผลการวิจัยในชั้นเรียนและนวัตกรรมครูแบบดิจิทัล — รองรับ workflow การส่ง-ตรวจ-ลงนามหลายขั้นตอน (ครู → หัวหน้ากลุ่มสาระ → ฝ่ายวิชาการ → ผู้อำนวยการ) พร้อม audit trail, ลายเซ็นอิเล็กทรอนิกส์/ดิจิทัล, และคลังผลงานที่ค้นหาได้ ออกแบบให้สอดคล้องกับพระราชบัญญัติธุรกรรมทางอิเล็กทรอนิกส์ (พ.ศ. 2544), PDPA, และระเบียบการเก็บรักษาเอกสารราชการ

## เอกสารออกแบบระบบ

ดูรายละเอียดฉบับเต็ม (กฎหมายที่เกี่ยวข้อง, workflow, data model, การจัดเก็บไฟล์, ความปลอดภัย, สแตกเทคโนโลยีที่แนะนำ, และแผนงาน MVP/Roadmap) ได้ที่ [`docs/system-design.md`](docs/system-design.md)

## MVP ที่ใช้งานได้แล้ว (Implementation)

MVP นี้ใช้ **Node.js ล้วนๆ แบบ zero-dependency** (ไม่มี `npm install`) เพื่อให้ **ฟรี 100%, มีประสิทธิภาพ, และรันง่ายที่สุด**:

- `node:http` — เว็บเซิร์ฟเวอร์และ router
- `node:sqlite` (built-in ใน Node ≥22.5) — ฐานข้อมูล ไม่ต้องติดตั้งเซิร์ฟเวอร์ DB แยก
- `node:crypto` — เข้ารหัสรหัสผ่าน (scrypt) และคำนวณ hash เอกสารล็อกเวอร์ชัน
- HTML/CSS/JS ธรรมดา (ไม่มีเฟรมเวิร์ก frontend) — mobile-first, ใช้งานง่าย

### วิธีรัน

```bash
node src/db/seed.js   # สร้างบัญชีผู้ใช้ทดลอง (รันครั้งแรกครั้งเดียว)
node server.js         # เริ่มเซิร์ฟเวอร์ที่ http://localhost:3000
```

### บัญชีทดลองใช้งาน (อีเมล / รหัสผ่าน)

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| ครู | teacher@school.ac.th | teacher123 |
| หัวหน้ากลุ่มสาระ | head@school.ac.th | head1234 |

### ฟีเจอร์ที่ทำแล้ว

- ระบบ login/RBAC ตามบทบาท (ครู/หัวหน้าสาระ/ฝ่ายวิชาการ/ผู้อำนวยการ/แอดมิน)
- ฟอร์มกรอกรายงานครบทุกฟิลด์ตาม data model + แนบไฟล์ (PDF/Word/รูปภาพ)
- Workflow ส่ง-ตรวจ-ลงนาม 4 ขั้นตอน (ครู→หัวหน้าสาระ→ฝ่ายวิชาการ→ผู้อำนวยการ) พร้อมส่งกลับแก้ไขได้ทุกขั้น
- ลงลายมือชื่ออิเล็กทรอนิกส์แบบวาดด้วยนิ้ว/เมาส์ (เก็บเป็นเวกเตอร์ ไม่ใช่รูปภาพ คมชัดทุกขนาดจอ)
- Audit trail ครบ: ผู้ลงนาม, เวลา, IP, ความเห็น และ **เพิกถอนลายเซ็นอัตโนมัติ**เมื่อมีการแก้ไขและส่งใหม่หลังถูกตีกลับ
- สร้างเอกสารฉบับอนุมัติที่ **ล็อกเวอร์ชัน** (SHA-256 hash) พร้อมลายเซ็นทุกขั้นตอน แสดงผลเป็น HTML ที่พิมพ์/บันทึกเป็น PDF ได้ทันทีจากเบราว์เซอร์ (รองรับภาษาไทยเต็มรูปแบบ)
- แดชบอร์ดสรุปสถานะ (นับจำนวนรายงานแยกตามสถานะ ตามขอบเขตที่แต่ละบทบาทเห็น) + ค้นหา/กรองตามชื่อเรื่อง กลุ่มสาระ ระดับชั้น ปีการศึกษา สถานะ
- สิทธิ์การเข้าถึงตามบทบาท: ครูเห็นเฉพาะงานตน, หัวหน้าสาระเห็นเฉพาะกลุ่มสาระตน, ฝ่ายวิชาการ/ผู้อำนวยการเห็นทั้งหมด
- **CSRF protection**: ทุกฟอร์มที่เปลี่ยนแปลงข้อมูลต้องแนบ token ที่ผูกกับ session ของผู้ใช้ ป้องกันการปลอมคำขอข้ามเว็บไซต์
- **รายการกลุ่มสาระแบบควบคุมได้**: แอดมินจัดการรายชื่อกลุ่มสาระที่หน้า "จัดการกลุ่มสาระ" ฟอร์มรายงานและฟอร์มผู้ใช้ดึงตัวเลือกจากรายการนี้เป็น dropdown แทนการพิมพ์ข้อความอิสระ ทำให้งานไปเข้าคิวหัวหน้าสาระที่ถูกต้องเสมอ
- **จำกัดจำนวนครั้ง login ผิด**: ล็อกการ login ชั่วคราว 15 นาทีหลังพยายามผิดครบ 5 ครั้งจาก IP เดียวกัน (แยก bucket ตาม IP ผู้เชื่อมต่อจริง ไม่ใช่ตามบัญชี จึงไม่ถูกใช้แกล้งล็อกบัญชีคนอื่น)
- **เปลี่ยนรหัสผ่านได้เอง**: ทุกบทบาทเปลี่ยนรหัสผ่านตัวเองได้ที่เมนู "เปลี่ยนรหัสผ่าน"

## Deploy ขึ้น Render

โปรเจกต์นี้ไม่มี dependency ให้ต้องติดตั้ง จึง deploy บน [Render](https://render.com) ได้ตรงไปตรงมา มี 2 วิธี:

### วิธีที่ 1: ใช้ Blueprint (ไฟล์ `render.yaml` ที่แนบมาให้แล้ว)

1. Push โค้ดขึ้น GitHub (ทำไปแล้วที่ branch นี้)
2. ที่ Render Dashboard → **New** → **Blueprint** → เลือก repo นี้ → Render จะอ่าน `render.yaml` แล้วตั้งค่าทุกอย่างให้อัตโนมัติ
3. กด **Apply** รอ deploy เสร็จ แล้วเปิด URL ที่ Render ให้มา (เช่น `https://research-report-system.onrender.com`) — ระบบจะสร้างบัญชีทดลองให้อัตโนมัติในการรันครั้งแรก (ไม่ต้องเข้า shell)

### วิธีที่ 2: ตั้งค่าเองผ่านหน้า Dashboard

1. **New** → **Web Service** → เชื่อมกับ repo/branch นี้
2. **Environment**: `Node`
3. **Build Command**: เว้นว่างไว้ หรือใส่ `true` (ไม่มี dependency ให้ติดตั้ง)
4. **Start Command**: `node server.js`
5. (แนะนำ) เพิ่ม Environment Variable `DATA_DIR=/var/data` แล้วแนบ **Persistent Disk** mount ที่ `/var/data` — ดูหัวข้อถัดไปว่าทำไมจำเป็น

### ⚠️ ข้อควรระวังเรื่องการเก็บข้อมูลถาวร (สำคัญมาก)

**แผน Free ของ Render ไม่รองรับ Persistent Disk** ไฟล์ฐานข้อมูล SQLite, ไฟล์แนบ, และเอกสารฉบับล็อกทั้งหมด **จะหายทุกครั้งที่ deploy ใหม่หรือเซิร์ฟเวอร์ restart** เพราะพื้นที่เก็บข้อมูลเป็นแบบชั่วคราว (ephemeral) — ใช้ได้สำหรับ **ทดลอง/สาธิตเท่านั้น**

เอกสารออกแบบระบบเองก็ระบุไว้ว่าเอกสารราชการต้องเก็บอย่างน้อย 10 ปี ดังนั้นสำหรับการใช้งานจริงต้อง:
- อัปเกรดเป็นแผน **Starter ขึ้นไป** แล้วแนบ Persistent Disk (ตามที่ตั้งค่าไว้ใน `render.yaml`) หรือ
- ย้ายไปใช้ managed database ภายนอก (เช่น Render PostgreSQL) + object storage ภายนอกสำหรับไฟล์แนบ (ต้องปรับโค้ดเพิ่มเติม เพราะปัจจุบันเขียนดีไซน์ไว้สำหรับ SQLite + ดิสก์โดยตรง)

### ข้อจำกัดที่ทราบอยู่แล้ว (สำหรับพัฒนาต่อ)

- เอกสารฉบับอนุมัติเป็น **HTML ที่ล็อกด้วย hash** ไม่ใช่ไฟล์ PDF จริงที่เซิร์ฟเวอร์สร้าง เนื่องจากสภาพแวดล้อมพัฒนานี้ไม่มีสิทธิ์เข้าถึง npm registry จึงไม่สามารถใช้ไลบรารี PDF ที่รองรับฟอนต์ไทย (การเขียน PDF parser/embedder ฟอนต์ไทยเองตั้งแต่ต้นมีความเสี่ยงสูงเกินไปสำหรับ MVP) ผู้ใช้กด "พิมพ์ / บันทึกเป็น PDF" จากเบราว์เซอร์เพื่อได้ไฟล์ PDF ที่แสดงผลภาษาไทยถูกต้อง
- ยังไม่มี PKI/ใบรับรองดิจิทัลตามมาตรา 26 ETA (เป็น e-Signature ทั่วไปแบบวาดลายเซ็น เหมาะกับการใช้งานภายในโรงเรียนตามที่ระบุในเอกสารออกแบบ)
- ไม่มี HTTPS ในตัว (ควรวางไว้หลัง reverse proxy ที่มี TLS เมื่อใช้งานจริง — Render ทำให้อัตโนมัติอยู่แล้ว)
- ไฟล์แนบเก็บบนดิสก์เครื่องเซิร์ฟเวอร์โดยตรง ยังไม่มีการเข้ารหัสไฟล์หรือสำรองข้อมูลอัตโนมัติ
- Rate limit และ CSRF อ่านค่า IP ผู้เชื่อมต่อจริงจากส่วนหัว `X-Forwarded-For` (จำเป็นเพราะอยู่หลัง reverse proxy ของ Render) — ถ้านำระบบไปเปิดให้เข้าถึงจากอินเทอร์เน็ตโดยตรงโดยไม่มี proxy ที่เชื่อถือได้อยู่ด้านหน้า ต้องตั้ง `TRUST_PROXY=false` มิเช่นนั้นผู้ใช้ปลอมส่วนหัวนี้เพื่อหลบ rate limit ได้
- การล็อกอินผิดพลาดใช้หน่วยความจำ (in-memory) เก็บสถิติ รีเซ็ตทุกครั้งที่เซิร์ฟเวอร์ restart — เพียงพอสำหรับกันการเดารหัสผ่านแบบสุ่มเบื้องต้น แต่ไม่ทดแทนการเฝ้าระวังความปลอดภัยระดับ production
